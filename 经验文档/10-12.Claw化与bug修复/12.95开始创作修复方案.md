## 一、V1.0合规性审查结论

V1.0修复方案经审查，存在以下违反设计原则的问题：

| 修复项 | 违反原则 | V1.0做法 | V2.0修正 |
|--------|----------|----------|----------|
| P0-1 | 业务参数硬编码在GUI层 | gui_main.py写死max_iterations=5 | 由GenerationService提供默认值，GUI不传则使用服务层默认值 |
| P0-2 | GUI层承担插件初始化职责 | expert_selector.py手动构建PluginContext | 由PluginRegistry.load_plugin_runtime()统一加载，ExpertSelector只负责选择 |
| P1-3 | 数据获取逻辑在GUI层 | gui_main.py新增_get_previous_chapters_text() | 由context-builder-v1插件或GenerationService内部获取前文 |
| P1-2 | GUI做格式适配 | gui_main.py适配GenerationResult | ExpertPlugin.generate()自行保证返回正确格式，GUI只负责显示 |

**核心修正原则**：
- 所有业务逻辑在插件层或服务层实现
- GUI层只做三件事：触发（调用服务方法）、显示（更新UI控件）、回调（处理结果展示）
- 数据获取（大纲/风格/人设/世界观/前文）由GenerationService内部编排，GUI只传递"项目上下文"引用

### P0-2: 专家模式插件加载职责错位

**位置**: `gui/expert_selector.py` 第340-412行 `load_expert_plugin()`方法

**问题**: `ExpertSelectorWidget`在GUI层手动实现了：importlib动态加载→PluginContext构建→initialize()调用→PluginRegistry.register()→PluginRegistry.activate()。这整个流程是`PluginRegistry.load_plugin_runtime()`的职责，ExpertSelector不应越权。

**根因**: `PluginRegistry.load_plugin_runtime()`方法已存在（第633行），但ExpertSelector没有使用它，而是自己重新实现了一套加载逻辑。

**V2.0修复方案**: ExpertSelector只负责选择专家和触发加载，实际加载由PluginRegistry完成。

```python
# expert_selector.py load_expert_plugin()方法重写

def load_expert_plugin(self, expert_id: str):
    """
    加载专家插件（V2.0修订 - 遵循微内核原则）
    
    设计原则：
    - ExpertSelector只负责选择和触发
    - 插件加载/注册/初始化由PluginRegistry统一管理
    - PluginContext由PluginRegistry内部构建（使用已有的核心服务实例）
    """
    if not self.plugin_registry:
        logger.error("PluginRegistry未初始化，无法加载专家插件")
        return None
    
    # 1. 先检查是否已加载
    existing = self.plugin_registry.get_plugin(expert_id)
    if existing and hasattr(existing, 'state') and existing.state.value == 'active':
        logger.info(f"专家插件 {expert_id} 已加载，直接返回")
        return existing
    
    # 2. 通过PluginRegistry统一加载（包含注册、初始化、激活全流程）
    success, error_msg = self.plugin_registry.load_plugin_runtime(expert_id)
    
    if success:
        plugin_instance = self.plugin_registry.get_plugin(expert_id)
        if plugin_instance:
            logger.info(f"专家插件 {expert_id} 加载成功")
            return plugin_instance
    
    logger.error(f"专家插件 {expert_id} 加载失败: {error_msg}")
    return None
```

**前置条件**: `PluginRegistry.load_plugin_runtime()`内部需要确保：
1. 正确构建PluginContext（使用ServiceLocator获取核心服务实例）
2. 调用plugin.initialize(context)
3. 注册和激活插件

如果`load_plugin_runtime()`目前不调用initialize()，需在该方法内补充：

```python
# core/plugin_registry.py load_plugin_runtime()方法中，注册后补充初始化：
if plugin_instance and hasattr(plugin_instance, 'initialize'):
    context = self._build_plugin_context()  # 内部方法，安全构建PluginContext
    if context:
        plugin_instance.initialize(context)
```

**风险评估**: 低。复用已有的PluginRegistry机制，逻辑更统一。

**合规性**: ✅ 插件加载职责回归PluginRegistry，GUI层只做选择和触发

### P1-3: 前文内容传递断裂

**位置**: 数据流层面，前文获取逻辑应在服务层

**问题**: GUI层新增`_get_previous_chapters_text()`方法获取前文内容，这是数据获取逻辑，应在服务层或插件层。

**V2.0修复方案**: 前文获取逻辑下沉到`GenerationService`内部。

**方案A（推荐）**: 在`novel_generation_service.py`的`generate_chapter_async()`方法中，如果`previous_chapter_text`为空，自动从项目数据中获取。

```python
# agents/novel_generation_service.py generate_chapter_async()方法中
# 在构建NovelGenerationConfig之前添加：

# 自动获取前文内容（如果GUI未提供）
if not previous_chapter_text:
    previous_chapter_text = self._get_previous_chapters_text(chapter_number)

# 新增内部方法：
def _get_previous_chapters_text(self, chapter_number: int) -> str:
    """从项目数据中获取前5章的文本内容（服务层职责）"""
    previous_text = ""
    try:
        # 尝试从ServiceLocator获取项目管理服务
        from core.service_locator import ServiceLocator
        project_service = ServiceLocator.get_service('project_manager')
        if project_service:
            for ch_num in range(max(1, chapter_number - 5), chapter_number):
                ch_data = project_service.get_chapter_content(ch_num)
                if ch_data:
                    previous_text += ch_data + "\n\n"
    except Exception:
        pass
    return previous_text[-6000:]  # 限制长度避免token溢出
```

**方案B（最小修改）**: GUI层保留`_get_previous_chapters_text()`作为临时方案，但标注为技术债务，待12.9数据管理外迁方案实施后迁移。

```python
# gui_main.py 保留现有实现，添加注释：
# TODO: 技术债务 - 此方法应在GenerationService中实现
# 待12.9数据管理外迁方案实施后迁移
previous_chapter_text = self._get_previous_chapters_text(chapter_number)
```

**合规性评估**: 方案A完全合规，方案B是过渡方案。

**建议**: 当前阶段采用方案B（最小修改，降低回归风险），后续12.9外迁时一并清理。
