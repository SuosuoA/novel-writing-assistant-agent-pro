## 二、数据流端到端验证发现的深层问题

V1.0修复仅解决了"接口层断裂"问题。在逐行追踪完整数据流后，发现以下**架构级断裂**：

### 核心发现：默认模式根本没有使用九维度评分

0.0项目说明宣称"九维度智能评分反馈循环"是核心创新，但实际数据流显示：

**默认模式路径**：
```
GUI._on_start_generation()
  → service.submit_async_generation()
    → NovelGenerationService.generate_chapter_async()
      → PipelineOrchestrator.execute_novel_generation()
        → _execute_pipeline_iteration()
          → novel-generator-v3.generate_chapter()
            → _validate_content()  ← 内联8维度简化评分
              → iterative-generator-v2.generate_with_iteration()
                → validation_fn = _validate_content  ← 传入简化评分函数
```

**专家模式路径**：
```
GUI._start_expert_generation()
  → ExpertSelector.load_expert_plugin()
    → ExpertPlugin.generate()
      → _evaluate_expert()  ← 九维度评分（expert-novel-v1/validator.py）
```

**问题本质**：`quality-validator-v1`插件虽然已升级为九维度，但**没有任何调用方使用它**。PipelineOrchestrator的validation阶段定义了`quality_validation` agent_type，但novel-generator-v3在内部自己做了评分，绕过了PipelineOrchestrator的validation阶段。

## 三、深层问题清单

### P0-NEW-1: novel-generator-v3内联评分与九维度标准不一致（架构断裂）

**位置**: `plugins/novel-generator-v3/plugin.py` 第719-815行 `_validate_content()`方法

**问题详情**:

| 维度 | 九维度标准（0.0项目说明） | novel-generator-v3实际 | 差异 |
|------|--------------------------|------------------------|------|
| 人设一致性 | 19% (character) | 19% ('人设') | 权重相同，但名称不一致 |
| 风格一致性 | 19% (style) | 19% ('风格') | 权重相同，但名称不一致 |
| 大纲符合性 | 13% (outline) | 13% ('大纲') | 权重相同，但名称不一致 |
| 世界观一致性 | 12% (worldview) | 12% ('世界观') | 权重相同，但名称不一致 |
| 知识库引用 | 8% (knowledge) | 8% ('知识点引用') | 权重相同，但名称不一致 |
| **写作技巧** | **8% (writing_technique)** | **缺失** | **整个维度缺失** |
| 字数符合性 | 8% (word_count) | 8% ('字数') | 权重相同，但名称不一致 |
| 上下文衔接 | 8% (context_coherence) | 10% ('上下文契合度') | **权重错误（10% vs 8%）** |
| AI感 | 5% (ai_feeling) | 11% ('AI感') | **权重严重错误（11% vs 5%）** |

**根因**: novel-generator-v3的`_validate_content()`是从V1.7时期复制过来的简化版，从未升级为V2.0九维度。它不调用quality-validator-v1插件，而是在内部独立实现了评分逻辑。

**影响**: 
- 默认模式下"写作技巧"维度完全缺失，8%的评分权重被AI感（11%）和上下文契合度（10%）瓜分
- 评分结果无法与专家模式统一对比
- 0.0项目说明中"九维度智能评分"在默认模式下是虚假宣传

## 四、二次修复方案

### 修复策略选择

**方案A（重构方案）**: 让novel-generator-v3调用quality-validator-v1插件做评分
- 优点：完全符合微内核架构，评分逻辑统一
- 缺点：改动大，novel-generator-v3与iterative-generator-v2的耦合需要重构
- 风险：高，可能破坏默认模式的生成流程

**方案B（最小侵入方案）**: 修复novel-generator-v3的_validate_content()，使其对齐九维度标准
- 优点：改动小，只改一个方法，不影响外部接口
- 缺点：评分逻辑仍然内联，没有调用插件
- 风险：低

**方案C（桥接方案）**: novel-generator-v3的validation_fn桥接到quality-validator-v1
- 优点：复用插件评分逻辑，改动适中
- 缺点：需要处理插件实例获取和初始化
- 风险：中

**建议**: 采用方案C（桥接方案），在novel-generator-v3的`generate_chapter()`中，将`validation_fn`从内联的`_validate_content()`改为桥接调用`quality-validator-v1`插件。

**新增桥接方法**:

```python
def _validate_via_plugin(self, content: str, target_word_count: int,
                         chapter_outline: str, style_profile: Optional[Dict],
                         characters: List[Dict], world_view: str,
                         knowledge_categories: Optional[List[str]] = None,
                         writing_techniques: Optional[List[str]] = None):
    """
    通过quality-validator-v1插件进行九维度评分（桥接方案）
    
    设计原则：
    - 复用插件评分逻辑，不在novel-generator-v3中重写评分
    - 如果插件不可用，返回None触发降级到内联评分
    - 返回格式与iterative-generator-v2期望的(total_score, dimension_scores, suggestions)一致
    """
    try:
        # 从PluginRegistry获取quality-validator-v1实例
        validator = self._get_quality_validator()
        if not validator:
            return None
        
        # 构建验证请求
        from core.models import ValidationRequest
        request = ValidationRequest(
            content=content,
            chapter_outline=chapter_outline,
            style_profile=style_profile or {},
            characters=characters or [],
            worldview=world_view or {},
            target_word_count=target_word_count,
            knowledge_categories=knowledge_categories or [],
            writing_techniques=writing_techniques or [],
        )
        
        # 调用插件验证
        result = validator.validate(request)
        
        if result and hasattr(result, 'total_score'):
            # 转换为iterative-generator-v2期望的格式
            dimension_scores = {}
            suggestions = []
            if hasattr(result, 'dimension_scores') and result.dimension_scores:
                dimension_scores = result.dimension_scores
            if hasattr(result, 'suggestions') and result.suggestions:
                suggestions = result.suggestions
            
            return (result.total_score, dimension_scores, suggestions)
        
        return None
        
    except Exception as e:
        self._logger.warning(f"[V3] 插件评分失败，降级到内联评分: {e}")
        return None

def _get_quality_validator(self):
    """获取quality-validator-v1插件实例"""
    try:
        if self._context and hasattr(self._context, 'plugin_registry'):
            registry = self._context.plugin_registry
            if registry:
                validator = registry.get_plugin('quality-validator-v1')
                if validator and hasattr(validator, 'validate'):
                    return validator
    except Exception:
        pass
    return None
```

**合规性**: ✅ 评分逻辑在插件层实现，novel-generator-v3只做桥接调用

def _validate_via_plugin(self, content, target_word_count, chapter_outline,
