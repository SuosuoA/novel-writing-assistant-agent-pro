此前的诊断文档（如 12.94 V9.3 报告）声称"九维度数据流完整闭环"，但实际真跑第一轮就发现评分引擎整体崩溃降级。**结论：验证必须真跑，不能走读。**

**保留的回归 harness**（tests/ 目录，即本项目缺失的"真跑集成测试"）：

| 文件 | 覆盖 |
|------|------|

### 1.3 高频反模式清单（本项目特有，修复时优先排查）

1. **吞异常兜底**：`except Exception → 默认分/默认值`，把真 bug 静默掩盖成"看着在跑实则全废"（专家评分全 0.5 案例）。
2. **残留门卫**：检查一个实际调用路径根本不用的依赖然后 raise（本次清了 4 处 `_api_client` 门卫）。
3. **下划线导入连字符插件**：`from plugins.style_learner_v5.plugin import ...` 永远 ImportError（插件目录是 `style-learner-v5`），本次清了 7 处，正确姿势是注册表优先 + `importlib.import_module("plugins.style-learner-v5.plugin")`。
4. **裸插件未初始化**：importlib 动态创建的插件实例必须调 `initialize(PluginContext)`，否则内部 `_config` 等状态缺失。
5. **人物数据形状**：GenerationDataService 输出 `{name: profile}` 字典，下游按 `list[dict]` 遍历会拿到 str 崩溃；且存在扁平（name 在顶层）与 V5 嵌套（basic_info.name）两种 dict。消费端必须归一化。

## 二、第一阶段：专家模式评分引擎修复（头号根因）

### 2.1 症状
九维度评分全部 0.5、总分恒 0.49、永不达标、6 轮空转、反馈全是"各维度偏低 50%"废话。

### 2.2 根因（plugins/expert-novel-v1/validator.py）
1. `_check_rule_violation` 假设世界观 rule 是 dict 调 `.get()`，但用户配置的 `rules` 是**字符串列表** → AttributeError；
2. `evaluate()` 外层 `except Exception → 全维度降 0.5`，把崩溃静默吞掉。

### 2.3 修复
- `_check_rule_violation` 兼容 str/dict 规则；
- `evaluate()` 重构为**逐维度独立 try 隔离**（单维异常只降该维为中性分，其余 8 维照常；数据流断裂 ValueError 仍上抛不掩盖）。

### 2.4 实测
总分 0.49→**0.7564**，9 维 7 个不同真实值；收敛测试逐轮 **0.760→0.771→0.782** 单调上升（反馈循环真实推动改进）。GUI 真实数据路径（含字符串规则世界观）8 维区分验证通过。

## 八、V1.1 补充修复（遗留事项清零，5 处）

### 8.1 插件签名机制鸡生蛋缺陷（发布阻断级）

**根因**（`core/plugin_loader.py` + `scripts/add_plugin_signatures.py`）：目录哈希把 `plugin.json` 自身算在内，但签名恰恰写回 `plugin.json` → 写入后目录哈希立即改变 → **任何签名一经写入即自我失效**。该机制自设计以来从未可能通过校验；生产模式（DEV_MODE=0）下全部插件会被 L3 拦截，软件根本无法发布。

**修复**（校验器与签名脚本同一算法，脚本直接复用校验器实现杜绝漂移）：
- 哈希**排除插件根目录的签名载体文件**（`plugin.json`/`plugin.sig`）；
- **manifest 完整性保护**：把「去除 signature 字段后的 manifest 规范化序列化（sort_keys）」纳入哈希——入口/权限声明被篡改仍可检出；
- **排序遍历**保证跨平台哈希确定性（原 `iterdir()` 顺序依赖 OS）；
- 签名脚本写入后**立即回验**（鸡生蛋缺陷的回归防线）。

**实测**（`tests/_audit_signatures.py`，生产模式子进程）：20/20 签名通过；篡改插件代码 → 检出且不影响其余插件；篡改 manifest 字段 → 检出；复原后全部通过。
