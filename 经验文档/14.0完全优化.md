## 一、验证方法论（本次工程的核心经验）

### 1.1 为什么静态走读不可信

此前的诊断文档（如 12.94 V9.3 报告）声称"九维度数据流完整闭环"，但实际真跑第一轮就发现评分引擎整体崩溃降级。**结论：验证必须真跑，不能走读。**

### 1.2 harness 真跑法

统一的 mock 接缝：`core.ai_service_manager.get_ai_service_manager`（专家模式、普通模式、续写、快捷创作全部走此统一入口）。mock 返回带 `.success/.text/.error/.usage` 的结果对象即可无 API 驱动全链路。

**保留的回归 harness**（tests/ 目录，即本项目缺失的"真跑集成测试"）：

| 文件 | 覆盖 |
|------|------|
| `tests/_audit_e2e_expert.py` | 专家模式 7 步循环 + 九维评分 + 记忆往返 + 收敛测试 |
| `tests/_audit_gui_path.py` | GUI 原始数据 → GenerationDataService → 专家插件全真实路径 |
| `tests/_audit_e2e_pipeline.py` | 普通模式：服务层 → PipelineOrchestrator → 五阶段 → final_output |
| `tests/_audit_e2e_normal.py` | novel-generator-v3 标准 generate(request) 接口 |
| `tests/_audit_features.py` | 快捷创作 / 续写 / 知识库验证 / 长篇检测 四功能链 |

### 1.3 高频反模式清单（本项目特有，修复时优先排查）

1. **吞异常兜底**：`except Exception → 默认分/默认值`，把真 bug 静默掩盖成"看着在跑实则全废"（专家评分全 0.5 案例）。
2. **残留门卫**：检查一个实际调用路径根本不用的依赖然后 raise（本次清了 4 处 `_api_client` 门卫）。
3. **下划线导入连字符插件**：`from plugins.style_learner_v5.plugin import ...` 永远 ImportError（插件目录是 `style-learner-v5`），本次清了 7 处，正确姿势是注册表优先 + `importlib.import_module("plugins.style-learner-v5.plugin")`。
4. **裸插件未初始化**：importlib 动态创建的插件实例必须调 `initialize(PluginContext)`，否则内部 `_config` 等状态缺失。
5. **人物数据形状**：GenerationDataService 输出 `{name: profile}` 字典，下游按 `list[dict]` 遍历会拿到 str 崩溃；且存在扁平（name 在顶层）与 V5 嵌套（basic_info.name）两种 dict。消费端必须归一化。

## 二、第一阶段：专家模式评分引擎修复（头号根因）

### 2.1 症状
九维度评分全部 0.5、总分恒 0.49、永不达标、6 轮空转、反馈全是"各维度偏低 50%"废话。

### 2.2 根因（plugins/expert-novel-v1/validator.py）
1. `_check_rule_violation` 假设世界观 rule 是 dict 调 `.get()`，但用户配置的 `rules` 是**字符串列表** → AttributeError；
2. `evaluate()` 外层 `except Exception → 全维度降 0.5`，把崩溃静默吞掉。

### 2.3 修复
- `_check_rule_violation` 兼容 str/dict 规则；
- `evaluate()` 重构为**逐维度独立 try 隔离**（单维异常只降该维为中性分，其余 8 维照常；数据流断裂 ValueError 仍上抛不掩盖）。

### 2.4 实测
总分 0.49→**0.7564**，9 维 7 个不同真实值；收敛测试逐轮 **0.760→0.771→0.782** 单调上升（反馈循环真实推动改进）。GUI 真实数据路径（含字符串规则世界观）8 维区分验证通过。

## 三、第二阶段：性能优化（启动 + 页面卡死）

### 3.1 启动 import 4.6s → 0.45s
- `infrastructure/__init__.py` 急加载 vector_store→lancedb(~1.9s)：改 PEP 562 `__getattr__` 惰性暴露；
- gui_main 顶层 matplotlib(~0.8s)/networkx(~0.2s)（仅人物图谱用）：改函数内局部导入。

### 3.2 热榜页 17s→0.19s、设置页 10.3s→0.06s（根因：Tk 渲染 emoji）
实测定位：**Windows 上 Tk 首次渲染 emoji 约 7s（字体回退枚举）+ 每个新 emoji 字形约 1s**，与所选字体无关、预热不可行（只是挪走卡顿）。楷体无 emoji 字形，界面 100+ 处 emoji。

修复：`MainWindow._install_emoji_text_patch()` 全局拦截 Label/Button/Checkbutton/Radiobutton/LabelFrame 的 text——装饰性 emoji（emoji+文字）剥掉 emoji 保留文字；纯图标按钮保留不动（另手动替换 👁→"显/隐"、🔄→"↻"）。热榜徽章 emoji 直接去除。

### 3.3 其他
- 默认启动页 热榜→工作台（原来 __init__ 期建热榜页+后台 exec_module 抢 GIL 卡 14s，且 mainloop 未启动导致渲染回调失败="热榜爬取不到"）；
- 热榜启动后 +8s 后台预拉（`_prefetch_hot_ranking_async`）+ 插件实例缓存（避免重复 exec_module）；
- DeepSeek V4 模型接入：config.yaml `deepseek-v4-pro`、下拉加 v4-pro/v4-flash、`core/online_provider.py` 模型表注册（max_tokens 64000，消除"未知的模型"降级 4096）。真机验证两模型均 `POST /chat/completions 200 OK`。

### 4.4 向量召回（L2 温记忆）——核心卖点此前从未真正工作

`infrastructure/vector_store.py` 三个召回方法（recall_knowledge/recall_similar_chapters/recall_similar_styles）把**字符串直接传 `table.search()`** → LanceDB 走全文检索路径需要 INVERTED 索引（未创建）→ 永远降级/静默失败。

修复：先 `embed_func.embed(query)` 再按向量搜（表内本有 vector 列，无需任何索引）。实测："修炼 灵气 突破境界" 语义召回到武侠雷火法门等相关条目。

## 五、接口契约备忘（供后续开发对齐）

- `QuickCreationRequest.keywords` 是 **str**（空格分隔），不是 list；
- `ContinuationResult` 正文字段是 **`.text`**，不是 `.content`；
- `PipelineExecutionResult.final_output` 为 dict：`{content, word_count, stats}`，stats 内含 `weighted_total_score/passed/dimension_scores`（ADR-010 合同）；
- `ValidationScores` 新增 `passed` 字段（插件层判定达标，Agent/GUI 直接读取）；
- content_generation 阶段 data 会 **merge 进 payload**（dict 不落 previous_output）。
