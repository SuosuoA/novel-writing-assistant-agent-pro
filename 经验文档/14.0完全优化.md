此前的诊断文档（如 12.94 V9.3 报告）声称"九维度数据流完整闭环"，但实际真跑第一轮就发现评分引擎整体崩溃降级。**结论：验证必须真跑，不能走读。**

**保留的回归 harness**（tests/ 目录，即本项目缺失的"真跑集成测试"）：

| 文件 | 覆盖 |
|------|------|

### 1.3 高频反模式清单（本项目特有，修复时优先排查）

1. **吞异常兜底**：`except Exception → 默认分/默认值`，把真 bug 静默掩盖成"看着在跑实则全废"（专家评分全 0.5 案例）。
2. **残留门卫**：检查一个实际调用路径根本不用的依赖然后 raise（本次清了 4 处 `_api_client` 门卫）。
3. **下划线导入连字符插件**：`from plugins.style_learner_v5.plugin import ...` 永远 ImportError（插件目录是 `style-learner-v5`），本次清了 7 处，正确姿势是注册表优先 + `importlib.import_module("plugins.style-learner-v5.plugin")`。
4. **裸插件未初始化**：importlib 动态创建的插件实例必须调 `initialize(PluginContext)`，否则内部 `_config` 等状态缺失。
5. **人物数据形状**：GenerationDataService 输出 `{name: profile}` 字典，下游按 `list[dict]` 遍历会拿到 str 崩溃；且存在扁平（name 在顶层）与 V5 嵌套（basic_info.name）两种 dict。消费端必须归一化。

## 二、第一阶段：专家模式评分引擎修复（头号根因）

### 2.1 症状
九维度评分全部 0.5、总分恒 0.49、永不达标、6 轮空转、反馈全是"各维度偏低 50%"废话。

### 2.2 根因（plugins/expert-novel-v1/validator.py）
1. `_check_rule_violation` 假设世界观 rule 是 dict 调 `.get()`，但用户配置的 `rules` 是**字符串列表** → AttributeError；
2. `evaluate()` 外层 `except Exception → 全维度降 0.5`，把崩溃静默吞掉。

### 2.3 修复
- `_check_rule_violation` 兼容 str/dict 规则；
- `evaluate()` 重构为**逐维度独立 try 隔离**（单维异常只降该维为中性分，其余 8 维照常；数据流断裂 ValueError 仍上抛不掩盖）。

### 2.4 实测
总分 0.49→**0.7564**，9 维 7 个不同真实值；收敛测试逐轮 **0.760→0.771→0.782** 单调上升（反馈循环真实推动改进）。GUI 真实数据路径（含字符串规则世界观）8 维区分验证通过。

## 八、V1.1 补充修复（遗留事项清零，5 处）

### 8.1 插件签名机制鸡生蛋缺陷（发布阻断级）

**根因**（`core/plugin_loader.py` + `scripts/add_plugin_signatures.py`）：目录哈希把 `plugin.json` 自身算在内，但签名恰恰写回 `plugin.json` → 写入后目录哈希立即改变 → **任何签名一经写入即自我失效**。该机制自设计以来从未可能通过校验；生产模式（DEV_MODE=0）下全部插件会被 L3 拦截，软件根本无法发布。

**修复**（校验器与签名脚本同一算法，脚本直接复用校验器实现杜绝漂移）：
- 哈希**排除插件根目录的签名载体文件**（`plugin.json`/`plugin.sig`）；
- **manifest 完整性保护**：把「去除 signature 字段后的 manifest 规范化序列化（sort_keys）」纳入哈希——入口/权限声明被篡改仍可检出；
- **排序遍历**保证跨平台哈希确定性（原 `iterdir()` 顺序依赖 OS）；
- 签名脚本写入后**立即回验**（鸡生蛋缺陷的回归防线）。

**实测**（`tests/_audit_signatures.py`，生产模式子进程）：20/20 签名通过；篡改插件代码 → 检出且不影响其余插件；篡改 manifest 字段 → 检出；复原后全部通过。

### 9.2 修复清单（14 处）

1. **GUIAsyncHelper 缺 `call_on_main_thread`**：生成的进度/完成/错误三回调全部 AttributeError 被服务层吞掉 → 生成在后台成功、界面永远空白。补公共方法+改为主线程UI泵模式（工作线程只入队，杜绝跨线程Tcl调用）。
2. **context_building 阶段每次报"Agent未注册"**：该阶段设计为内置（无独立Agent）但仍按Agent查找。编排器补内置处理 `_build_context_stage_data`（前章上下文规整透传）。
3. **前章上下文在 agent 接缝被丢弃**：payload 的 previous_chapters/previous_chapter_text 从未到达生成插件 → 会话恢复后"上下文记忆前5章"失效。novel_generation_agent 提取+`seed_previous_chapters()`（插件新增种子方法，内部自累计优先、保持5章上限）。
4. **逆向分析 LLM 从未接入**：找的 `llm_client` 服务与 `llm.api_key` 配置键从未存在 → 永远静默降级规则检测。接入统一 `get_ai_service_manager()`（与其他功能同一入口）。
5. **逆向"应用修正"不落地**：只改两个内存字段（世界观修正整个丢弃）、"刷新"只改状态栏文字。重写：三类设定更新 current_project + sync_module_data + 界面树刷新。附带：分析结果陈旧缓存问题（规则降级时代的空结果被持久化缓存永远命中）→ 缓存键加版本盐 `ANALYZER_CACHE_VERSION`。
6. **快捷/续写加载器草台**：快捷写错类名（`QuickCreatorPlugin`≠实际 `QuickCreationPlugin`）→ 恒 None → 报"请先配置AI服务"误导用户；两者都绕过内核注册表裸导入且不初始化、依赖已废弃 set_api_client。重写为注册表优先 + `_init_naked_plugin` 降级。
7. **快捷结果显示字段断裂**：GUI 读 `.content` 但 Result 模型没有该字段（世界观/大纲/情节用 `get_full_text()`，人物是 `List[CharacterResult]`）→ 生成成功界面空白。四处显示回调全修。
8. **快捷单项生成必崩**：传不存在的 `detail_level` 参数（四个方法签名都没有）→ TypeError。按真实签名重写四个调用。
9. **长篇检测在工作线程读 Tk 变量**：跨线程 Tcl 调用（未定义行为）。参数提升到主线程读取。
10. **错误路径 lambda 晚绑定 `e`（5处）**：except 块结束后 `e` 被删除 → 错误显示自身崩溃（错误被二次吞掉）。长篇检测/世界观导入/人物导入/大纲解析/生成错误回调全修（默认参捕获）。
11. **知识库双重暗病**：两个同名 `_on_knowledge_refresh`（带 reload_cache 的被静默覆盖 → "刷新缓存"按钮从不重载缓存）+ 状态栏报总数但列表只插200条（计数与所见不符）。合并为一个方法（重载+刷新+诚实计数，上限500并明示）。另删被覆盖的旧版 `get_selected_writing_techniques` 死代码。
12. **`_set_status` 线程安全化**：多个后台任务在工作线程直接调它写 Tk 变量。本体做主线程路由，全部调用点免改。
13. **3 个"开发中"死按钮实现**：大纲导出（txt/json 双格式）、生成结果导出TXT、导出DOCX（python-docx）。另有 6 个未绑定的占位处理器（反哺四件套/快捷save）确认为孤儿死代码不影响用户。
14. **误导文案修正**：插件加载失败的报错不再让用户去"配置AI服务"（与API无关）。
15. **续写结果显示界面卡死（py-spy 活体抽栈定位）**：主因是 `_highlight_version_in_tree` 每次先 `selection_remove` 全部再 `selection_set` —— 每次选择变化触发新 `<<TreeviewSelect>>` 事件 → handler → `_display_version` → 再高亮 → **无限事件乒乓**（非嵌套递归，重入 guard 防不住），主线程被选择事件占满。修复=高亮幂等化（已是目标选择直接返回，事件链一步收敛）+ `_display_version` 重入防护 + `configure(text="⭐最佳")` 的 emoji 改纯文字（configure 不经 emoji 拦截器，首渲染 ~7s/字形是叠加病灶）。
16. **动态 emoji 渲染病灶系统性根治**：`.config/.configure(text=…)`、`StringVar.set`、`Treeview insert values`、`Text.insert` 四类动态路径都绕过原 emoji 拦截器（只拦构造参数）。两层处置：① **拦截器扩展**——configure/config、StringVar.set、Treeview.insert 三个公共入口全局剥离（一处修全类含未来代码；纯图标按钮保留不变空白）；② Text.insert 不拦（可能承载正文/用户数据，剥离会污染导出），其 app 级 emoji（生成日志/知识库详情面板一次10个字形≈10秒卡顿/清理结果等约30处）逐处改纯文字。颜色继续承担语义区分，外观不受影响。**教训：动态状态文本一律不用 emoji**。
17. **逆向分析对真实项目数据形状崩溃**：项目文件中大纲是 dict、世界观是 list，分析器直接 `outline[:1000]` 切片 → `KeyError(slice)` 整体失败。新增 `_normalize_setting_text()` 在 `analyze_consistency` 入口归一化（LLM 与规则两路径都受益）。
18. **续写单版本评分调用不存在的私有方法**：`_evaluate_version` 从未存在 → 生成成功后必抛 AttributeError（结果被丢弃）。改用公共接口 `select_best_version([result], request)` 取评分详情。

## 十、跨板块数据流与全工作流验证（集成层）

> 单板块功能达标（第九节）后，验证板块**之间**的数据流是否按设计闭环。

### 10.1 发现的断裂：ProjectManager 跨板块接口整体缺失（12 个方法）

真跑扫描 GUI 调用的 `_project_manager.*` 方法 vs 现役接口，发现 **GUI 调用了 12 个
本类根本不存在的方法** —— V5 迁移时 ProjectManager 接口大面积丢失，导致四条
跨板块数据流全部 `AttributeError` 断裂（且都在 `try/except` 里被吞成"请先打开项目"）：

| 数据流 | 断裂方法 | 后果 |
|--------|---------|------|
| 快捷创作 → 项目 | set_worldview/set_outline/set_characters/set_plot | 快捷产物"导入项目"一点就报错 |
| 项目 → 续写 | get_outline/get_characters/get_worldview/get_recent_chapters | 续写拿不到项目设定与前文 |
| 项目 → 续写/长篇选章 | list_chapters/get_chapter_content | "选择章节"永远空 |
| 续写/生成 → 项目 | add_chapter/update_current_chapter | 续写"保存到项目"报错、章节无处沉淀 |

**修复**（`services/project_manager.py` V2.3，"新增不改旧"补齐 13 个接口）：
- 设定读写：set_*/get_*，读取自动归一化（dict 大纲/list 世界观 → 续写需要的 str/List[Dict]）；
- 章节 CRUD：规范章节形状 `{title,content,word_count,source,created_at}`，
  list_chapters/get_chapter_content/get_recent_chapters/add_chapter（同名覆盖）/update_current_chapter。

### 10.2 补上设计流程第 7 步：生成章节沉淀

评分反馈循环设计的第 7 步"完成并沉淀记忆"在 GUI 从未实现——生成结果**只显示不入项目**，
不手动复制就丢，且续写选章/长篇选章/前5章参考都取不到刚生成的章节。
新增 `_sediment_generated_chapter()`：生成完成回调里把章节写入 `completed_chapters`
（打开项目→项目管理器；未打开→内存态待保存带走）。

### 10.3 打通生成 → 逆向数据流

`_on_reverse_refresh_chapters` 原先只重算已上传章节——项目里生成/续写沉淀的章节
不出现，用户得手动重新上传自己刚生成的内容。现在刷新时把项目 `completed_chapters`
按标题去重并入逆向章节列表。

### 10.4 集成验证结果（`_audit_workflow.py`）

**14/14 全绿**，完整闭环真跑打通：
A. 快捷四件套写入项目 → B. 项目设定驱动开始创作（**断言生成提示词真实包含项目人物名**）→
C. 生成章节沉淀 → D. 续写选章/长篇选章/前5章参考同源读取 → E. 续写调用项目上下文生成 →
保存回项目 → F. 生成/续写章节在逆向分析可见 → G. 逆向基于项目设定分析+修正反哺 →
H. 项目保存→磁盘→重新加载往返完整（章节内容与世界观设定均留存）。
