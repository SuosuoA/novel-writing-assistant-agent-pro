## 二、验证流程

### 2.1 自动验证结果解读

| 评分维度 | 权重 | 阈值 | 说明 |
|----------|------|------|------|
| 世界观一致 | 12% | ≥0.8 | 设定元素匹配度 |
| 人设符合 | 19% | ≥0.8 | 人物性格一致性 |
| 大纲匹配 | 13% | ≥0.8 | 情节要点覆盖率 |
| 风格一致 | 19% | ≥0.8 | 风格特征匹配度 |
| 知识点引用 | 8% | ≥0.7 | 知识库知识点覆盖率 |
| 写作技巧 | 8% | ≥0.7 | 修辞/描写/叙事技巧运用 |
| 字数达标 | 8% | ≥0.7 | 实际字数/目标字数 |
| 上下文衔接 | 8% | ≥0.7 | 前后文连贯性 |
| AI感 | 5% | ≤0.3 | AI痕迹检测（越低越好） |

### 2.2 人工验证步骤

1. **阅读生成内容**：完整阅读AI生成的章节内容
2. **对照大纲检查**：验证主要情节是否覆盖
3. **检查人物塑造**：对话、行为是否符合人设
4. **验证世界观一致性**：设定、术语是否准确
5. **评估风格匹配**：文笔、节奏是否符合预期
6. **记录问题清单**：标注需要修复的具体位置

## 四、修复操作指南

### 4.1 修复优先级

1. **P0（阻塞性问题）**：情节遗漏、逻辑矛盾、设定冲突
2. **P1（严重问题）**：OOC、对话失真、AI痕迹
3. **P2（一般问题）**：节奏失衡、形象模糊、风格割裂
4. **P3（轻微问题）**：措辞不当、标点错误

### 4.2 修复方法

#### 4.2.1 情节修复

```
步骤：
1. 定位问题段落
2. 分析缺失/冲突的具体内容
3. 手动补充或修改情节
4. 确保与前后文衔接自然
```

**示例**：
- 问题：大纲要求"主角发现隐藏密室"，但正文直接跳过
- 修复：补充发现过程描写，包含环境描写、心理活动

#### 4.2.2 人物修复

```
步骤：
1. 对比人物设定档案
2. 标注不符合人设的对话/行为
3. 重新设计符合性格的表达
4. 保持人物弧光的一致性
```

**示例**：
- 问题：高冷角色突然话痨
- 修复：精简台词，改为简短有力的表达

#### 4.2.3 风格修复

```
步骤：
1. 对比风格学习样本
2. 识别AI痕迹特征（如"璀璨""深邃"等高频词）
3. 替换为更自然的表达
4. 调整句式节奏
```

**示例**：
- 问题："他的眼眸深邃如星空"
- 修复："他盯着她，眼睛一动不动"

#### 4.2.4 世界观修复

```
步骤：
1. 查阅世界观设定文档
2. 标注设定冲突点
3. 修正为正确设定
4. 补充必要的设定说明
```

**示例**：
- 问题：金丹期使用了元婴期的能力
- 修复：调整为金丹期合理的能力范围

### 2026-04-13 逆向反馈字段类型修复（V1.49.50）

**问题**: 分析失败，错误`expected string or bytes-like object, got 'dict'`
**现象**: 上传章节后点击"运行分析"，报错`expected string or bytes-like object, got 'dict'`

**根因分析**:
1. **personality字段类型不一致**: 人物设定中`personality`可能是字符串、字典（`{"核心性格": "乐观"}`）或列表（`["乐观", "开朗"]`）
2. **ability字段类型不一致**: 同样可能是字符串、字典或列表
3. **代码假设是字符串**: 第706行`personality.replace()`假设`personality`是字符串，但实际可能是字典

**架构合规修复（只在插件层修改）**:
| 文件 | 位置 | 修改 |
|------|------|------|
| reverse_feedback_analyzer.py | 第686-697行 | 添加`ability`字段类型检查 |
| reverse_feedback_analyzer.py | 第702-718行 | 添加`personality`字段类型检查 |

**关键代码**:
```python
# V1.49.50修复：personality可能是字典或列表
personality = char.get("personality", "")
if isinstance(personality, dict):
    # 从字典中提取文本（常见格式：{"核心性格": "乐观", "优点": "..."}）
    personality = " ".join([str(v) for v in personality.values() if v])
elif isinstance(personality, list):
    # 列表格式：["乐观", "开朗"]
    personality = " ".join([str(p) for p in personality if p])
elif not isinstance(personality, str):
    personality = ""
```

**架构合规性**:
- ✅ **业务逻辑在插件模块实现**: 字段类型转换在插件层完成
- ✅ **UI只负责显示和传递**: GUI层未修改
- ✅ **最小化修改**: 只添加字段类型检查逻辑

### 2026-04-09 V1.49.36 专家模式7步迭代循环+记忆闭环（P0核心架构修复）

**修复人**: 高级开发工程师

**版本**: V1.49.36

**严重级别**: P0（专家模式缺少迭代循环，导致评分不达标时无法自动优化重试）

#### 问题描述

用户设计的生成流程为7步闭环：
1. 数据打包（世界观/风格/大纲/人物/知识库/技巧/上下文/字数/【本章完】）
2. 发送API请求 → 接收文章
3. 九维度评分 + 切实可行的修改方案
4-5. 不达标 → 带反馈再次请求（循环迭代）
6. 达标输出成果
7. 总结经验输入Claw化记忆(mem9)，用于自我优化

但实际代码中，`expert-novel-v1/plugin.py` 的 `generate()` 方法只做一次"生成→评分→返回建议"就结束了，**完全没有迭代循环**。同时 `_enhance_request()` 不回读历史经验——Step7存了但下次生成时不读取。

#### 修复内容（4项核心改动）

| 编号 | 优先级 | 问题 | 修改文件 | 方法 | 状态 |
|------|--------|------|----------|------|------|
| P0-A | P0 | 专家模式缺少迭代循环（只做单次评分） | expert-novel-v1/plugin.py | `generate()` 重写为完整for循环(≤max_iterations) | ✅ |
| P0-B | P0 | 历史经验不回读（越用越聪明断裂） | expert-novel-v1/plugin.py | `_enhance_request()` 添加ExpertMemory回读 | ✅ |
| P0-C | P0 | 历史经验不注入prompt（底层LLM看不到） | expert-novel-v1/plugin.py | `_call_base_generator()` 添加`_build_experience_prompt()` | ✅ |
| P1-D | P1 | 迭代反馈构建缺失 | expert-novel-v1/plugin.py | 新增`_build_iteration_feedback()`方法 | ✅ |

#### 关键代码变更详情

**1. `generate()` 方法完全重写**（~200行新逻辑）:
```
旧流程: enhance → call_base → evaluate → return (无循环)
新流程: enhance → for iteration in range(max):
           call_base → evaluate → check_pass?
           YES → break输出 / NO → build_feedback → continue
         store_memory → return best_result
```

**2. `_enhance_request()` 新增历史经验回读**:
```python
# 从ExpertMemory检索历史评分和优化方案
prev_eval = self._expert_memory.retrieve_evaluation(chapter_id)
similar_solutions = self._expert_memory.retrieve_similar_issues(common_issues)
enhanced.historical_evaluation = prev_eval
enhanced.historical_solutions = similar_solutions
```

**3. `_call_base_generator()` 新增历史经验注入到prompt**:
```python
# 将历史经验追加到大纲内容（最可靠的LLM prompt注入路径）
experience_hint = self._build_experience_prompt(hist_eval, hist_solutions)
request.outline_data['content'] += experience_hint
```

**4. 新增 `_build_iteration_feedback()` 方法**:
- 构建结构化反馈文本（维度评分+具体问题+修改建议）
- 注入下一轮请求的大纲内容中
- 让LLM针对性改进

def _publish_ai_config_loaded(self) -> None:
    """启动时发布AI配置加载事件，通知AI状态管理插件"""
    try:
        # 直接获取EventBus（避免依赖ConfigService的内部状态）
        from core.event_bus import get_event_bus, Event
        
        event_bus = get_event_bus()
        if not event_bus:
            logger.warning("[配置加载] EventBus不可用，跳过事件发布")
            return
        
        # 构建AI配置字典（从UI变量获取）
        ai_config = {
            "service_mode": self._service_mode_var.get(),
            "provider": self._provider_var.get(),
            "model": self._model_var.get(),
            "api_key": self._api_key_var.get(),
            "local_url": self._local_url_var.get(),
            "temperature": self._temp_var.get(),
        }
        
        # 发布config.changed事件

                'data': ai_config
            },
            source='MainWindow._load_settings_from_config'
        )
        event_bus.publish(event)
        logger.info(f"[配置加载] 已发布AI配置事件: provider={ai_config['provider']}, mode={ai_config['service_mode']}")
        
    except Exception as e:
