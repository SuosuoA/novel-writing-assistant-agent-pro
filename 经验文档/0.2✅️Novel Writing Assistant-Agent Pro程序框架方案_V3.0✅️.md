#### 1.1.2 V5核心流程：评分反馈循环

**【评分反馈，循环优化生成流程】强制保护机制**:

```
1. 上下文构建 → 2. AI生成 → 3. 质量验证 → 4. 评分判断
       ↓                                          
       └─────────┐                                
                 ↓                                
      5. 反馈生成 │ → 6. 迭代优化（最多5次）        
                 ↓                                
              7. 完成                            
```

**5大核心规则**（强制保护）:
1. 【本章完】标记必须出现
2. 评分阈值0.8（低于则继续迭代）
3. 迭代上限5次
4. 9维度智能评分权重不可修改
5. 上下文记忆前5章

**V1.49.30补充**（权重要归属原则）:
6. 评分计算权归属插件层，GUI不硬编码权重、不计算评分、不判断达标
   - `novel-generator-v3` 返回 `weighted_total_score` + `passed`
   - `expert-novel-v1` 返回 `ValidationScores.total_score`
   - `quality-validator-v1` 提供维度映射唯一真值来源

> **详细保护机制见**: 第十五章 V5强制保护机制

```
┌─────────────────────────────────────────────────────────────────┐
│                         用户界面层 (Tkinter)                      │
│  主窗口 → 工作台(Notebook) → 设置面板 → 插件管理                    │

                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
┌───────────────────────┐ ┌───────────────┐ ┌───────────────────────┐
│   微内核核心 (Kernel)   │ │  插件系统      │ │   服务层 (Services)    │
│  EventBus             │ │ PluginRegistry│ │   AI API服务           │
│  PluginRegistry       │ │ Loader        │ │   文件服务             │
│  ServiceLocator       │ │ HotSwap       │ │   记忆服务             │
│  ConfigManager        │ │               │ │                        │
└───────────────────────┘ └───────────────┘ └───────────────────────┘
                                    │
                                    ▼
                    ┌───────────────────────────────┐
                    │      插件层 (16个插件)         │
                    │  Analyzer/Generator/Validator │
                    │  Tool/Expert                  │
                    └───────────────────────────────┘
```

### 2.2 核心设计原则

#### 微内核原则
核心系统仅提供最基本的服务（插件调度、事件分发、依赖管理），所有业务功能通过插件实现。

#### 榫卯式集成
插件与核心通过标准接口"咬合"，接口定义严格，实现灵活。

#### 事件驱动
插件间通过EventBus通信，解耦依赖。

> **详细接口规范见**: 《1.1项目总体架构设计说明书修订执行版✅️.md》

## 四、微内核核心引擎

### 4.1 事件总线 (EventBus)

**核心职责**: 插件间发布-订阅通信

**关键接口**:
```python
class EventBus:
    def subscribe(self, event_type: str, handler: Callable) -> str
    def unsubscribe(self, subscription_id: str) -> bool
    def publish(self, event_type: str, data: Any, source: str = None)
    def publish_sync(self, event_type: str, data: Any, timeout: float = 5.0) -> List[Any]
```

**实现增强**: 重试机制（最多3次）、死信队列（最大1000条）、超时控制（默认5秒）

### 4.2 插件注册表 (PluginRegistry)

**核心职责**: 管理所有已加载的插件

**关键接口**:
```python
class PluginRegistry:
    def register(self, plugin: BasePlugin) -> bool
    def unregister(self, plugin_id: str) -> bool
    def get_plugin(self, plugin_id: str) -> Optional[BasePlugin]
    def get_plugins_by_type(self, plugin_type: PluginType) -> List[BasePlugin]
```

### 4.3 服务定位器 (ServiceLocator)

**核心职责**: 提供核心服务的依赖注入

**设计要点**: 单例模式、线程安全、循环依赖检测

### 4.4 配置管理器 (ConfigManager)

**配置结构**:
```yaml
app:
  name: "Novel Writing Assistant-Agent Pro"
  version: "6.0.0"

ai:
  provider: "deepseek"
  model: "deepseek-chat"
  temperature: 0.7

plugins:
  directories: ["plugins"]
  hot_reload: true
```

## 六、Agent深度集成

### 6.1 MasterAgent架构

**专家Agent清单**:

| Agent | 职责 | 关键能力 |
|-------|------|----------|
| Thinker | 深度思考推理 | CoT（思维链）、ToT（思维树） |
| Optimizer | 迭代优化 | 反馈驱动、自我修正 |
| Validator | 质量验证 | 多维度评分、规则检查 |
| Planner | 任务规划 | 目标分解、依赖分析 |

### 6.2 Agent协作模式

- **链式协作**: Planner → Thinker → Optimizer → Validator → Planner（循环）
- **树状协作**: Planner分发任务到多个Thinker，汇总后Optimizer优化
- **网状协作**: Planner与Validator持续验证，多个Thinker并行思考

### 6.3 Agent执行约束

| Agent | 超时 | 重试 | 降级策略 |
|-------|------|------|----------|
| Thinker | 30s | 1次 | 跳过CoT，直接推理 |
| Optimizer | 20s | 1次 | 返回原始生成结果 |
| Validator | 15s | 0次 | 返回默认评分0.5 |
| Planner | 10s | 0次 | 使用上一次计划 |

> **详细设计见**: 《1.3Agent系统详细设计文档✅️.md》
